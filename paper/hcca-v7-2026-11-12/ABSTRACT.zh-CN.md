# HCCA 面向代码仓库修复的 Token 效率研究

技术报告，2026 年 11 月 12 日。

## 摘要

代码阅读、测试输出与执行纠错会不断增加编码 Agent 后续请求的输入历史。HCCA 通过全局复用的角色提示词和每次委派独立的 worker 上下文，将阅读与执行细节保留在对应任务内，由上层 Agent 负责规划和结果整合。

本文报告冻结 v7 的直接执行配置在社区选取的 SWE-bench Verified Mini 全部 50 题上的结果。HCCA 通过 36 题，DSH 极简 high 基线通过 35 题。HCCA 的 1 道未完成题计入 50 题分母、获得零分，其全部调用与用量仍计入费用。

| 指标 | HCCA 冻结 v7 | DSH 极简 high |
| --- | --- | --- |
| 全量通过率 | 36/50，72% | 35/50，70% |
| 官方已评测 | 49 | 50 |
| 实际模型请求 | 1,301 | 2,014 |
| 输入 tokens | 36,810,516 | ≥106,265,446 |
| 缓存输入 tokens | 35,849,984 | ≥104,137,856 |
| 完整记录中的缓存占比 | 97.3906% | 97.9979% |
| 输出 tokens，已含推理 | 654,304 | ≥4,050,837 |
| 完整记录中的推理 tokens | 408,903 | 3,690,753 |
| 统一谷价归一费用 | $0.644212152 | ≥$3.062054268 |

两组均使用 GXWTF 的 `deepseek-v4.1-flash` 和两题并发。HCCA 执行使用 low，DSH 使用 high，基线沿用此前已完成的运行。DSH 有一条用量不完整记录，表中的完整用量汇总构成总费用与 token 数下界。

HCCA 的归一费用至多为基线已知费用下界的约 21.04%，可证明的费用降幅至少为 78.9%。相对于基线完整记录，输入减少约 65.4%，输出减少约 83.8%。所记录输出差额的约 96.6% 来自推理字段，推理强度差异会影响这一结果的解释。

## 实验范围

本文测量的是直接 low executor 配置。Root 在本地派发任务，首次执行前省略固定模型规划调用。运行时支持的多层协作、独立 reader 和执行中引导功能仍需要各自的效果评测。当前 Official 0.2.1 经过封装及 Windows、DSH 集成更新，与本次冻结的 v7 运行快照具有各自的版本标识。

该题单包含社区数据集 `MariusHobbhahn/swe-bench-verified-mini` 的全部 50 题。结论适用于这一固定子集和单次配置比较。提示词、工具、上下文策略与推理强度共同变化，需要同推理强度的消融实验才能估计各项机制的独立贡献。

统一费用采用每百万 tokens 缓存输入 $0.003、未缓存输入 $0.15、输出 $0.60。推理计入输出一次。归一费用与 GXWTF 实际账单分别记录。
